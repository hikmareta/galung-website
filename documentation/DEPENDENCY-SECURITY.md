# Dependency security maintenance — 28 October 2026

Payload 3.92.0 resolves deepmerge 4.3.1. The registry reports LOW [GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4); [upstream issue 273](https://github.com/TehShrike/deepmerge/issues/273) describes dangerous-key checks bypassed by null-prototype targets, placeholder values and target copying. No upstream fixed version was available during this remediation. No application exploitability or global prototype mutation is asserted solely from that advisory.

The pinned pnpm patch `patches/deepmerge@4.3.1.patch` unconditionally removes `__proto__`, `constructor` and `prototype` string keys from enumeration of both source and target, including recursive merges. CJS, UMD and source copies are patched; public runtime bundles are tested. Source `index.js` references an upstream build-only dependency absent from the released runtime dependency graph; its exact patched fingerprint is verified rather than claiming it was executed. Normal symbols, nested objects, arrays, custom merge behavior and clone=false remain covered. Dangerous names are intentionally dropped even if an application would otherwise treat them as ordinary data. Do not use this package for preserving those names.

`pnpm install --frozen-lockfile` enforces the committed patch hash. `pnpm audit:policy` independently checks package version, patch mapping, patch-file hash and all three installed file fingerprints (line endings normalized), executes exploit/compatibility regressions, then runs the **full** registry audit. It retains the raw JSON in `.tools/dependency-audit.json`; CI uploads that file. The raw audit still exits 1 while the registry lists the original version. The policy passes only the exact LOW advisory on deepmerge 4.3.1 after mitigation verification, and fails on unknown advisories, other versions/severities, inconsistent counts, registry errors, missing/drifted patches or failed tests. This is a disclosed local mitigation, not a claim of a clean raw audit or an upstream fix.

Maintenance owner: dependency/application maintainer. Every policy run rechecks the registry. Track upstream, replace the patch with a verified compatible fixed version when available, then update fingerprints, lockfile and tests deliberately; never add broad audit ignores. Retest Payload integration, schema migration/restore and production build after changing merge behavior. External build provenance, signing, hosting and provider policies have independent activation gates.
